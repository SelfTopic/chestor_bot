# Промокоды — план

Живой документ, как остальные в `docs/design/`: решения дописываются сюда по мере обсуждения.
Главные правила решены (часть 0), детали каждой награды решаются, когда до неё доходит работа.

## Как читать

- ✅ **решено** — договорились, можно делать.
- 🔲 **открыто** — нужно решение владельца, без него не начинать.
- 💡 **идея** — можно сделать, но не обязательно.

## Часть 0 — зачем и главные правила

✅ **0.1. Зачем.** Промокоды — поощрение игры и причина следить за каналом @chestor_channel:
владелец публикует код в посте, кто успел, тот забрал. Возможность бесплатной награды — ещё
и повод подписаться на канал и стать гулем.

✅ **0.2. Только для гулей.** Промокоды — часть `ghoul_routers`: активировать может гуль,
подписанный на канал (обе проверки уже стоят на роутере).

✅ **0.3. Промокод — набор наград.** Один код может дать несколько наград сразу (CheSton,
RC-клетки, сытость, сброс кулдаунов…). Каждый тип награды — отдельный небольшой класс:
новые типы добавляются без переделки остального.

✅ **0.4. Ограничения.** При создании задаётся число активаций и, по желанию, срок. Один
игрок активирует один код один раз.

✅ **0.5. Название задаёт владелец.** Любое слово без пробелов, регистр не важен:
`промо мне_больше_не_нужны_промокоды`.

✅ **0.6. Создание — многострочной командой** (только владелец, `ADMIN_IDS`; права для
помощников — часть E плана маркетинга). Первая строка — название, число активаций и срок,
дальше по строке на награду:

```
+промо лето 30 24ч
честоны 1000
рс 200
сытость
сброс кд
```

Бот отвечает сводкой: название, активации, срок, список наград.

Короткая форма, как раньше, — только CheSton, без строк наград: `+промо лето 500 30` (500 CheSton,
30 активаций). Срок всегда пишется с единицей (`24ч`, `3д`, `30 мин`), поэтому формы не путаются.

✅ **0.7. Два этапа.** Сначала награды, которые меняют значения: CheSton, RC-клетки, прогресс
уровня, статы, сытость, здоровье, сброс кулдаунов. Потом временные эффекты («без кулдаунов
на час»): для них нужна новая механика.

Сделано: основа (таблицы `promo_codes` и `promo_activations`, создание в обеих формах,
активация `промо <название>`) и награды: CheSton (`честоны`, `честон`, `чс`), RC-клетки (`рс`, `клетки`; засчитываются
и в заработок за жизнь, `lifetime_rc_earned`), прогресс уровня (`прогресс 50` — проценты;
через `LevelUpService.add_progress`, как бои: на 100% — уровень с обычными наградами и
уведомлением, остаток сгорает, за раз не больше одного уровня), статы (`сила`, `ловкость`, `скорость`, `здоровье`/`хп`,
`реген` — по строке на стат; не выше потолка уровня, как при покупке: ошибка в коде не
сломает баланс боёв; упёрся — получает остаток, и ответ это показывает), сытость (`сытость` — полная,
`сытость 30` — +30%; как еда, `GhoulService.restore_hunger`: не выше 100%, расписание
уведомлений о голоде пересчитывается), полное здоровье (`лечение`, `хил`; метка регена и
расписание уведомлений двигаются вместе со здоровьем) и сброс всех кулдаунов (`сброс кд`).
Первый этап готов.
Остальные награды первого этапа добавляются по одной.

✅ **0.8. Управление кодами** (только админы). `/promo <название>` — карточка кода rich-таблицей:
статус (действует, истёк, разобран, удалён), награды, активации «N из M», срок и сколько
осталось, кто и когда создал и удалил. Кнопка «Удалить» с подтверждением. `/promos` — все коды
таблицей по 8 на страницу, кнопка с названием открывает карточку, из карточки — назад к списку.

Удаление мягкое: код перестаёт активироваться, но строка и активации остаются, и карточка
удалённого кода видна. Название уникально только среди живых кодов, поэтому после удаления его
можно занять снова; `/promo` по такому названию покажет живой код, а если его нет — последний
удалённый.
